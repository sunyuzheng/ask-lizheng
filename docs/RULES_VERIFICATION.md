# 回答规则修订验证

2026-11-01。比较基线为 Ask `9f813e97626709e0a271468162828aa11c0a0d1f`（审核的 `efc554c` 之后只有隐私操作文档变动），公开资料固定为 Open Context `7095f8de26f393966a36a5e2b9286084e1893000`。本记录区分已测结果和待完成的上线验收，不把结构检查当成回答质量。

## 方法

[evidence-benchmark.json](../tests/fixtures/evidence-benchmark.json) 包含 60 问、30 个同义问法组，分成开发集44问和留出集16问。问题来自公开原文，包含概念、应用、找资料、嘉宾、时间边界、追问、库外及身份不明问题；没有读取私人问答或未公开资料。它是独立于判断卡的首批原文基准，尚不能代表真实流量的完整分布。每组两个问法不能当作两份独立观察，汇总按组计算。

27 个原文参考来自26个公开文件，路径、文件哈希、说话人与字面锚点可验证。锚点在测量前从原文挑选，未从被测系统生成。公布的参考摘录和锚点每份合计不超过450字；私有评审在需要时从同一哈希原文加载锚点附近上下文。开发测量前后修正过两道 Ryo 问法与公开摘录长度，修正过程记在 fixture；初步未完成回答样本丢弃，正式比较使用相同冻结 fixture。

`scripts/evidence_eval.py` 只在显式 `--refresh-vectors` 时联网；新旧实现共用同一问题向量。分别报告文件出现、实际模型 excerpt 中原文锚点出现、来源资格、来源预算与检索耗时。没有锚点不自动等于答案错误：别的片段可能提供充分依据；命中锚点也不自动等于答对。

`scripts/answer_benchmark.py generate` 直接调用各版本的生产检索、生成、规范化和校验函数，每问三轮；不调用公开提问接口，不计额度、不存公开问答、不保存模型内部推理。完整提示词、实际证据和输出只存于忽略的 `.local/rules-revision-20261101/`，文件权限0600。基线代码逐文件与 git 提交核对，语义文件逐字节一致；派生 store 分别构建，未绕过版本或路径校验。

`judge` 每个成对样本随机交换 A/B，由 gpt-5 按合同六项标准评审，看到独立原文参考、好回答要求和各回答实际收到的片段与标注。系统提示词不向评审展示，避免泄露版本及重复占用上下文。检索遗漏后诚实地说明不足与任务完成分别记分；生成/校验失败和评审失败单列，不静默排除。三轮采样用于观察回答差异，不能证明评审无偏或所有题型稳定。

复跑（真实调用需进程环境中的服务令牌）：

```sh
python scripts/evidence_eval.py --refresh-vectors --split dev --output .local/evidence-dev.json
python scripts/answer_benchmark.py generate --split dev --repeats 3 --output .local/answers-current.json
# --implementation 指向固定基线代码及同一公开资料的独立目录
python scripts/answer_benchmark.py generate --implementation /path/to/baseline --split dev --repeats 3 --output .local/answers-baseline.json
python scripts/answer_benchmark.py judge --baseline .local/answers-baseline.json --candidate .local/answers-current.json --output .local/paired-dev.json
```

## 删除和机制测试

开发集38个有原文参考的问法，原实现锚点命中14/38，文件命中34/38。首次候选强制按语义窗口截取时为12/38与34/38；隔离实验确认变化来自截取方式，同说话人去重修改没有造成锚点得失。强制窗口方案找回 `compound-1`，丢掉 `scores-2`、`market-2`、`wanglu-1`，不作为默认上线。只在未进入词法候选的语义候选上使用命中窗口，开发集恢复14/38；其余情况保留旧定位。保留位置的机制有价值，不等于强制使用它已经证明有效。

下表是在首次12/38候选上、同一冻结开发集和向量的单变量消融，不能当作最终版本分数：

| 改动 | 实际片段锚点 | 文件出现 | 证据集合变化的问法 |
| --- | --- | --- | --- |
| 无手写近义扩展 | 11/38 | 33/38 | 7 |
| 无口头词改写 | 11/38 | 34/38 | 19 |
| 无标题猜测降权 | 12/38 | 34/38 | 1 |
| 无判断卡候选注入 | 12/38 | 34/38 | 24 |
| 判断卡固定加分改为排名融合 | 11/38 | 34/38 | 23 |

没有据此批量删除或更换这些默认方法。总数相同也不等于同题保持不变：去掉卡片有一题得、一题失。标题猜测尚不能迁移为上游内容类型事实，因为本次没有修改公开资料合同；本地不能凭猜测补一个“事实”字段。表中未测的旧启发式也没有假称已完成删除测试。

姓名边界另用目录360个称呼的五种生成问法共1,800次匹配，配合11个原有错误人名及小写外文姓氏负例。放宽字符/后续词限制能提高召回，但把“孙宇晨”类更长名字或未收录外文姓氏认成已有嘉宾。原姓名判定保留；这些数字只是身份匹配诊断，不是嘉宾回答准确率。
