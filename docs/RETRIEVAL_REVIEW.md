# 检索轨迹与复盘

2026-11-15。本轮把检索各阶段留下可核对的记录，沿用三个产品仓库和 Open Context 的职责。公开问答不接入个人 Claude Code、Codex 对话或私有知识库。

## 资料、候选与回答

Open Context 维护原文、目录、说话人与许可。回答服务的 `ContextIndex` 决定资料可以用于找入口、解释问题还是代表某人的观点；词法、语义、阅读地图和定向读取都经过同一资格检查。目录命中不能补出正文，说话人未确认的文字不能变成立正的观点。

`ContextReader` 为每次请求管理候选、资格缺口和阶段记录。它复用预建的 SQLite 与语义索引，不增加数据库、模型服务或新的资料副本。默认路径仍是全库词法与语义融合、原文选材、生成和校验。常规问题不增加模型调用。

缺口是本轮检索的处理结果。例如某个相关条目缺正文，或正文的发言归属未确认。它只进入私人诊断记录，不作为回答证据，也不表示全库或作者从未谈过。最终回答与公开出处继续经过原来的字段白名单。

## 私人轨迹 v1

Builder 在现有签名 `finish` 顶层发送可选 `retrieval_trace`，主站将其原子写入同一记录的 `retrieval_trace_json`。Ops 仅通过现有 owner 鉴权提供读取、导出和详情折叠区；公开问答、分享、发现列表和公开文件没有这个字段。

轨迹只含资料 commit、release hash、引擎 hash，以及各阶段的公开来源编号、片段编号、排名、耗时和固定原因。它不含用户背景、历史、改写查询、原文正文或模型思考。编号来自实际公开资料；普通 Markdown 也带稳定 `fragment_id`，最终 S 编号重排不影响匹配。

约束为16 KiB、8个阶段、每阶段24条、12个缺口。Node 拒绝无效新轨迹；Python 先校验并冻结，诊断无效就省略。完整存档仍受262144字节总包上限约束，若可选轨迹导致超限则只省略轨迹。首个 finish 获胜，丢失确认后的重试保持同一正文。轨迹随记录保留，整条删除一并删除，内容移除操作会清空它；私人备份沿用既有30天规则。旧记录没有轨迹，不回填或猜测历史步骤。

## 怎样复盘

从 owner 后台导出一页记录，放到本仓库忽略的 `.local/` 下：

```sh
python scripts/review_retrieval.py \
  --input .local/ops-export.json --output .local/retrieval-review.json
```

这个命令不联网、不调用模型、不重新提交提问。报告区分阶段间来源消失和同一来源换了窗口，保留版本与资格缺口；不再复制问题和答案正文。文件与报告必须留在 `.local/`，已有输出不会覆盖。没有轨迹的历史记录明确标记为无法还原。

先看哪个阶段丢了来源，再回到该 commit 的原文检查：未被召回、融合后掉出、选材剔除、生成未引用，是不同问题。再固定一个最小问题与原文锚点，加入独立回归，并找至少一个反例。访客的说法、AI 回答和一次修正都不会自动写成作者观点或全局检索规则。

旧题集可用 `evidence_eval.py --allow-compatible-context` 在后续资料版本上离线复跑。必须先通过每份金标准的文件哈希、原文锚点、说话人和连续单元检查，且每份参考都有固定哈希；保留原 fixture commit，报告另记实际资料 commit，不把旧测量改名为新版结果。已有查询向量继续复用。

## 试验与采用边界

在 Open Context `5807c87c298c8b3cbb3ad6c1332bd14122a8fdaf` 上，既有60题和另一批16题共76题复用了原查询向量。每题额外沿目录读取来源的原文锚点命中没有改善：分别仍为23/54和8/16。来源更丰富但不能据此声称答案更好，因此未采用每题目录扩读。另一种优先铺开八个来源家族的离线方案使60题命中从23/54降至22/54，也未采用。

另用4个公开或合成问题进行新旧各一轮真实模型试验，覆盖学习门槛、未确认发言及两个其他话题。八次生成均完成，本地单题约7至11秒。候选方案改善了一例未确认发言的表述，但没有一次主动提出补搜，两版都漏掉了预先指定的学习门槛原文。这个样本不能证明整体质量提升，模型自觉发现证据缺口的策略未通过采用条件；试验已收尾，不为改善分数重复采样。

有上限的补查原型保留在开发入口 `answer_benchmark.py generate --experimental-context-supplement`，生产不启用。它复用一次选材调用，至多执行一次补查，目录与全库搜索共用资格规则，最终候选不超过12，临近原回答期限时跳过。任何真实调用仍须遵守 [付费实验规则](EXPERIMENTS.md) 的同一累计计划和预算。

后续要检验的是子问题、来源与窗口的覆盖，而非为某个产品添加别名或强行放行未确认说话人。当前学习门槛案例仍是未解决的覆盖问题；轨迹让下一次失败可以定位，不能把它当成召回已修好的证明。

## 合并与发布顺序

Ops owner reader → 主站签名 writer → Builder trace sender。先发布消费者和兼容 writer，再发布发送方；回滚 Builder 后，旧读写仍兼容。三个仓库分别审核和发布，Open Context 本轮没有内容变更。生产验收只读 health、meta、已有 owner 记录和公开投影，不向 `/api/ask` 提交测试问题。容器仍须通过256MB下峰值低于200MB的既有 CI 门禁。
