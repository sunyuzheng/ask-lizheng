# 问问立正的产品决定

它是通向立正公开材料的问答入口。Open Context 拥有材料，产品负责让人找到、理解并使用它们；Builder Space 提供模型与运行环境。

第一版面向已经看过立正内容、但还带着疑问的观众，以及第一次来、需要一个具体入口的人。首页直接提供可使用的输入框，六个问题展示它擅长的范围：AI 学习、工作价值、产品判断、表达、良质与职业选择。点选只预填，不直接发送，鼓励改成自己的问题。

两种问法体现不同任务：「想明白」解释观点及关系，打开「结合我的处境」后把材料联系到具体目标和约束；「从哪读起」帮助选择先读哪些原文，与主页按关键词即时搜索的入口分工。选填背景只问目标、事实／卡点、试过什么；允许用户把初步诊断作为假设，不要求先填完一张完整人生问卷。

回答以理解为目标。先给真正回应问题的判断，再按需要解释机制、条件或下一步。AI 的综合与应用会标出；来源作为同一阅读体验的一部分，桌面宽屏在右侧，中小屏放到回答下方。来源附上为什么与当前问题有关、原始片段和日期；有视频字幕时链接到实际匹配位置。追问按钮仍先放进输入框，用户可以修改。

等待也是阅读体验的一部分。本地检索先展示真实候选材料，语义匹配后再更新；等待卡直接呈现两份材料的摘录，并允许展开更多出处。查找、匹配、整理、核对阶段由服务器事件驱动，等待时长来自页面时钟，显示实际使用的模型，随时可以停止。候选与最终采用的来源分开标注；停止或模型失败仍能读材料。这里展示执行状态与公开依据，不把模拟的“思考过程”当成模型事实。已校验的完整段落可提前逐段阅读，最终回答核验后替换；显示的是资料和整理方向，不转发原始模型思考。

首页可见的身份说明和「怎样用好它」共同设置预期：基于公开材料的 AI、不是本人实时回复；没有私有知识或最新新闻承诺。对于缺少个人条件的问题，先回答已知部分，最多追问两个关键缺口。对于语料之外的问题，说明材料不足。模型断连时保留检索结果，使故障状态仍可使用。

Context infra 将原文、AI 整理的判断卡和按问题组装的证据包分层；检索使用 source family 去重、词法与语义候选、问题别名和子问题覆盖。判断卡关联适用条件、范围不同的材料与具体案例，实际回答仍须回到原文。近期阅读地图只作导航，不与本人原文拥有同等证据权重。技术细节、数字与具体工作流保留适用条件；不能把某次大规模数据案例机械套进个人写作。回答中的链接、摘录和时间码由服务器从候选来源生成，模型只选编号。

问答保持页面内存中的对话体验，账号与额度仅保存必要服务端元数据。材料更新在上游完成，产品复制受校验的版本；修复服务或换模型不会改写立正的材料。未来扩展应来自真实使用中出现的不足：漏掉的来源、错误归属、回答没有解释清的关系，以及用户带回的新结果。

2026-10-01：用户要求默认改用DeepSeek V4 Flash，并保存提问。新页面会在输入旁明确说明30天保留，后台仅记录提示版本为v1、已受理的问题文本和最少回答元数据，不关联账号，不保存背景、历史、完整回答或模型思考。旧客户端不开始新记录。记录写入不阻塞回答；该新增批次须经准确差异审阅后启用，见[QUERY_RECORDS.md](QUERY_RECORDS.md)。

2026-10-01：独立页按lizheng.ai的视觉语言重做（象牙底、森林绿、思源宋体标题、立正印章），去掉左侧栏及其中与入口重复的按钮。原来的三个入口里，「聊聊我的问题」只是「想明白」加上个人处境，又与「补充背景」重复，因此合并为「想明白」下的「结合我的处境」开关：打开即按apply回答，并只在打开时发送处境；对话中发送后收成一行摘要。「找内容」改为「从哪读起」，强调AI导读，与主页的关键词搜索（「记得关键词？直接搜文章和视频」）区分。对话中输入框固定在底部，出处在宽屏右侧、中小屏放在回答下方；额度、保存提示和说明入口放在输入框下方同一行。仅有材料时如实写「找到的原文」，不显示模型名。思源宋体自托管、首屏后异步加载；带哈希的`/assets/`文件长期缓存，页面本身不缓存。

2026-10-01：完整回答可以「保存图片」（一张长图，手机上直接调起系统分享）或「下载PDF」（A4分页，出处可点）。两者都在浏览器内用canvas绘制，按lizheng.ai的视觉：顶部立正印章与问问立正，依次是问题、回答、这个回答的边界、出处（导出时按1到n连续编号，正文角标随之改写，不留回答未用材料的编号空缺），底部写明AI根据公开材料整理、不是本人实时回复，并附回到ask.lizheng.ai的二维码。不包含用户填写的处境；只找到材料、追问补充信息的结果不提供导出。导出代码按需加载，不发往服务器。

2026-10-02：首页「别人在问什么」。真实问答比编的示例更值得读：AI挑选整理、在Ops发布的问答显示在输入框下方，替代「不知道从哪问起」的示例；没有已发布问答时照旧显示示例。不分排序：第一次来看到被问得最多的几个主题，之后每次刷新换一批（优先没看过的，偏向常见主题，本机记住看过哪些）。登录后可以点「有帮助」，攒够点赞再考虑高赞。主页和本页面都只做首页卡片，独立浏览页以后再说。卡片点开在原地展开完整回答和出处，「问个类似的」只预填输入框；点赞需要登录，游客只看计数。数据来自lizheng.ai的公开发现接口`/api/ask-lizheng/discovery/*`（ask.lizheng.ai同源转发），在别的域名读取失败时安静地退回示例。

2026-10-02：「别人在问什么」自动来。v4说明上线后，新提问里不带处境的首轮问答，由AI去掉个人信息、判断值不值得看、归到主题后直接发布（立正可随时撤下），首页和「看更多」页从这些里取。之前v1/v3的提问不公开，即使去掉个人信息：当时没告诉提问者会公开。

2026-10-02：用户要求看清这个页面给社区、会员、课程带来多少转化。用Vercel Web Analytics计页面访问和几类点击：提问（区分手打、示例、卡片、追问、补充处境）、打开卡片与问个类似的（区分第一次来和再来）、点赞、Founding说明与验证结果、会员链接（按位置，链接带`utm_source=ask-lizheng`）、社区链接、出处点击（文章、视频、社区）。脚本只在lizheng.ai域名加载，本地与Builder域名不计数；事件只带入口和一个枚举值，不含提问内容或身份。购买归因（推荐码）暂不做。

2026-10-01候选：用户补充要求提问及回答都持续存档。v3保存提示对应完整已核验问答、采用的来源快照及匿名会话指标；服务端确认最终归档后才发送result。旧v1仍30天自动过期，缺失的历史回答不重新生成冒充。只增加Ops及必要存档行为，保留最新会员解释、Logto、模型、额度和页面设计。
