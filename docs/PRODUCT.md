# 问问立正的产品决定

问问立正是公开问答入口。Open Context拥有立正的公开材料，产品让人找到、理解并使用它们；用户在提问前同意保存和公开使用问题、完整回答与出处，让同一个问题帮助更多人，并用于改进回答和内容选题。Builder Space提供模型与运行环境。

2026-10-04用户再次明确：以公开问答、用户同意公开为产品和叙述的基础。输入旁先讲公开用途；App单独同意页同时讲清AI接收方和公开范围，按钮写「同意AI处理与公开使用」。分享是取得链接和传播问答的功能，公开使用的同意在提问时完成。处境原文不保存、不单独公开，但完整回答可能引用其中细节，这些细节也在公开使用的范围内。邮箱、登录身份及服务运维信息仍按各自的用途处理。历史v1/v3记录遵循当时的提示和范围。

Builder负责人于2026-10-04核实：当前deepseek-v4-flash生成请求转发到DeepSeek官方API；text-embedding-3-small检索请求转发到OpenAI。Builder的AI网关只留用量元数据，不保存问答正文。AI服务商及其用途在App发送前分别列明；训练、保留和保护承诺只按已核实的适用服务条款陈述。同日正式[Builder隐私与数据处理说明](https://space.ai-builders.com/privacy)上线：HTTPS/TLS、密钥哈希、限制访问和依法协助删除；DeepSeek可能保留输入并改进模型，当前没有API训练退出机制，不提供默认不训练或零保留承诺。App同意页直接披露这一点并链接正式说明，本机同意范围升级为v4以重新询问已有用户。公开教室定位说明用户愿意公开哪些问答，数据保护仍按实际处理链和这份政策说明。

第一版面向已经看过立正内容、但还带着疑问的观众，以及第一次来、需要一个具体入口的人。首页直接提供可使用的输入框，六个问题展示它擅长的范围：AI 学习、工作价值、产品判断、表达、良质与职业选择。点选只预填，不直接发送，鼓励改成自己的问题。

两种问法体现不同任务：「想明白」解释观点及关系，打开「结合我的处境」后把材料联系到具体目标和约束；「从哪读起」帮助选择先读哪些原文，与主页按关键词即时搜索的入口分工。选填背景只问目标、事实／卡点、试过什么；允许用户把初步诊断作为假设，不要求先填完一张完整人生问卷。

回答以理解为目标。先给真正回应问题的判断，再按需要解释机制、条件或下一步。AI 的综合与应用会标出；来源作为同一阅读体验的一部分，桌面宽屏在右侧，中小屏放到回答下方。来源附上为什么与当前问题有关、原始片段和日期；有视频字幕时链接到实际匹配位置。追问按钮仍先放进输入框，用户可以修改。

等待也是阅读体验的一部分。本地检索先展示真实候选材料，语义匹配后再更新；等待卡直接呈现两份材料的摘录，并允许展开更多出处。查找、匹配、整理、核对阶段由服务器事件驱动，等待时长来自页面时钟，显示实际使用的模型，随时可以停止。候选与最终采用的来源分开标注；停止或模型失败仍能读材料。这里展示执行状态与公开依据，不把模拟的“思考过程”当成模型事实。已校验的完整段落可提前逐段阅读，最终回答核验后替换；显示的是资料和整理方向，不转发原始模型思考。

首页可见的身份说明和「怎样用好它」共同设置预期：基于公开材料的 AI、不是本人实时回复；没有私有知识或最新新闻承诺。对于缺少个人条件的问题，先回答已知部分，最多追问两个关键缺口。对于语料之外的问题，说明材料不足。模型断连时保留检索结果，使故障状态仍可使用。

Context infra 将原文、AI 整理的判断卡和按问题组装的证据包分层；检索使用 source family 去重、词法与语义候选、问题别名和子问题覆盖。判断卡关联适用条件、范围不同的材料与具体案例，实际回答仍须回到原文。近期阅读地图只作导航，不与本人原文拥有同等证据权重。技术细节、数字与具体工作流保留适用条件；不能把某次大规模数据案例机械套进个人写作。回答中的链接、摘录和时间码由服务器从候选来源生成，模型只选编号。

问答保持页面内存中的对话体验，账号与额度仅保存必要服务端元数据。材料更新在上游完成，产品复制受校验的版本；修复服务或换模型不会改写立正的材料。未来扩展应来自真实使用中出现的不足：漏掉的来源、错误归属、回答没有解释清的关系，以及用户带回的新结果。

## 回答里不再露出内部编号，出处按1到n编号（2026-10-04）

检查线上发现，85个公开问答里有5个的回答或出处说明写着「S1 说得更直接」「可与S1、S2相互印证」。S 编号是模型挑材料用的内部标签，读者看不懂。服务器原来的检查认不出紧挨着中文的「S1」，而且只管编号存不存在，不管它是不是以角标出现。

- 编号只能以角标出现在摘要、正文和「这个回答的边界」里。把编号当名字写进句子，或写进标题、追问、出处说明的，请模型改写一次（和点名立正那条规则一样）；改写后仍有，或时间不够改写，服务器把编号换成出处的标题，能显示角标的地方再加角标。这次改写本身出错（超时、格式不对）时，读者拿到的是第一份回答，不会因为改措辞而没有回答。整理公开问答（`/api/curate`）也这样处理。
- 出处原来沿用检索时的编号，用到哪几份就显示哪几个，会跳号（1、2、3、8），保存图片和PDF却按1到n重排。现在回答完成时就按读者读到的先后编为1到n，网页、分享页、公开问答页和图片、PDF一致。生成中先显示的段落仍用候选材料的编号，完成后换成最终编号。之前存下的回答不改，仍可能跳号。
