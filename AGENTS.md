# Ask Lizheng

User-facing name: 问问立正. A source-grounded AI interface over lizheng-open-context.

- Use only the explicitly public Open Context projection for retrieval and answers. Never read private personal context, messages, community content or unpublished drafts. The authorized account integration may read only the signed-in user's verified identity and Circle Founding Member tag for access checks; never include these in model context.
- Open Context remains the content owner. data/context is a disposable, pinned copy with release hashes and license attribution.
- AI answers are AI synthesis/application, never Yuzheng replying live. Guest or community ideas retain their speakers; repository syntheses do not prove his stance. Answers name 立正 only for his own published writing or solo talks (`content_origin` yuzheng-published-text or yuzheng-spoken-source); when a sentence names him while citing other sources, the server asks for one rewrite.
- Models select only retrieved source IDs. Server owns links, dates, timecodes and excerpts. Do not trust generated URLs or claim quotations without exact matching.
- At the user's explicit request, v1 disclosed question-only records remain unlinked and expire after their original 30 days. With ASK_OPS_ENABLED and the displayed v3 notice, new admitted questions are saved before generation; the complete validated public-facing answer and its selected source snapshots are saved before SSE result delivery. Retain v3 archives until the owner manually deletes them. v3 additionally saves pseudonymous browser/conversation IDs, server-assigned turn number, question character count, intent and entrypoint for private usage metrics; never describe browser IDs as verified people. Do not persist email, account identifier, IP, separately submitted background/history or raw model reasoning. An archived answer may quote background; disclose this. Under the v4 notice (2026-10-02, now the announced notice) the start record also carries notice_version v4, has_background ("1" whenever a situation or an earlier turn took part) and, until 2026-10-04, the situation text, kept for the owner only and never published. Ops' automatic feed asks /api/curate, signed with a key derived for that purpose alone, for one eligible question's public version: identifying details removed, worth-showing judged, topic named; it never sees visitors, conversations or situations. For the user-approved first batch, /api/themes reads earlier questions' text once and returns only fresh generic questions that never repeat an asker's wording, and /api/seed-answer answers such a question like /api/ask without quota or records. All three routes take proofs bound to their own path. An answered v4 result also carries `share` (record id, the model's topic word from its `slug`, and an HMAC proof under the quota-store key with prefix `ask-share:v1:`); only that page can ask lizheng.ai to give it a page at ask.lizheng.ai/s/<day>/<word>, which shows the question and answer, never the situation, and stops only when the record is deleted. The owner decided (2026-10-04): what can be shared goes to search engines, every shared page; sharing is a feature, not consent, so askers cannot withdraw a link; and the situation is no longer kept: since then the v4 start record carries has_background and an empty context, /api/meta says context_archive false, and the page says so where the situation is written. Missing-notice clients are excluded; v1 is never silently expanded or migrated. Browser history stays in memory. Account scope remains daily3 public answers and verified Founding Member unlimited, with opaque quota metadata and encrypted short-lived authentication records. Sign-in may temporarily preserve the unsent draft in tab sessionStorage; clear on recovery. Analytics stays within the user-approved conversion scope (2026-10-02): Vercel Web Analytics page views and named click events, loaded only on lizheng.ai hosts; each event carries `surface` and at most one enumerated value, never question or situation text, source titles or identifiers. No other analytics. Inside the iPhone app (user agent `AskLizhengApp/`) the surface is `app`, membership purchase links and prices stay hidden (App Store guideline 3.1.1) while Founding verification stays, and the page tells the app through `window.webkit.messageHandlers.askApp` when pull-to-refresh would lose nothing. Before the app's first question the page asks once for permission to send it to the AI service (App Store guideline 5.1.2) and remembers the answer on the device; keep that step and its privacy policy link whenever data use changes.
- Model credentials are server-only; never put them in source, frontend, tests, screenshots or deployment env payloads.
- Public deploy, repository publication/push and upstream Open Context release require the exact reviewed payload and destination plus explicit user approval.
- Test source attribution, response validation, input bounds, unsupported questions and upstream failures. Keep deployment compatible with Builder Space: root Dockerfile, PORT, one worker, 256 MB.
